# pd001 product descriptor format

Each product of an IRIX distribution ships a descriptor file (e.g.
`dist/eoe`) next to its IDB (`dist/eoe.idb`) and image archives
(`dist/eoe.sw`, ...). The descriptor is the authoritative source of the
product → image → subsystem hierarchy and of the installation semantics;
the IDB only contributes file entries.

This document describes the confirmed binary grammar. It is a reader's
specification: everything here is either observable on real media or
confirmed against the tools that write these files.

## Primitives

All integers are big-endian. `LP16` is a length-prefixed string: a BE16
byte count followed by that many Latin-1 bytes (no terminator). The
length is a *signed* 16-bit value on the writer side, so no legitimate
string exceeds 32767 bytes.

```text
BE16  = 16-bit big-endian integer
BE32  = 32-bit big-endian integer
LP16  = BE16 length + Latin-1 bytes
```

## File structure

```text
file = header body
header = "pd001V" 3 digits "P" 2 digits NUL        (13 bytes total)
body = BE16 0x07c4, BE16 0x0001, BE16 0x07c3       (stream magic)
       BE16 layout_level
       product
```

The header's `VxxxPxx` numbers are a *generation id* chosen by the
writing tool's output mode; they are neither the body layout version nor
the IRIX release of the medium (one distribution mixes several header
variants). Readers dispatch on `layout_level` only.

`layout_level` is the minimum format level the product's features
required, 5 to 9:

| level | features introduced |
|-------|---------------------|
| 5 | base grammar: id/desc, order, version, replaces, prereq, follows |
| 6 | incompat ranges |
| 7 | product-level attributes (mach only) |
| 8 | image/subsystem attributes, conditional flags, autominiroot, disk-space accounting |
| 9 | updates ranges |

## Records

Fields guarded by `[Ln]` are present from layout level `n` on.

```text
product   = LP16 name
            LP16 id                        (one-line title)
            BE16 flags
            BE32 stamp
            [L5] LP16 desc                 (long description)
            [L7] attributes                (mach blobs only at level 7)
            BE16 image_count
            image[image_count]

image     = BE16 flags
            LP16 name                      (short name, e.g. "sw")
            LP16 id
            BE16 legacy_field              (always 2; meaning unknown)
            BE16 order                     (spec `order`; default 9999)
            BE32 version
            [L5] BE32 reserved, BE32 reserved   (always 0)
            [L5] LP16 desc
            [L8] attributes
            BE16 subsystem_count
            subsystem[subsystem_count]

subsystem = BE16 flags
            LP16 name
            LP16 id
            LP16 mapping                   (IDB record mapping expression)
            BE32 legacy_ordinal            (see below)
            BE16 count + range[count]      (replaces/obsoletes/follows)
            BE16 count + clause[count]     (prereq)
            [L5] LP16 desc
            [L6] BE16 count + range[count] (incompat)
            [L8] attributes
            [L9] BE16 count + range[count] (updates)

clause    = BE16 range_count + range[range_count]
range     = LP16 product, LP16 image, LP16 subsystem,
            BE32 low, BE32 high
attributes = BE32 count + LP16 blob[count] (one tag byte + payload text)
```

Every record carries two text fields: `id` (the one-line title) and
`desc` (the long description). `desc` is empty on all observed media;
readers fall back to `id` when it is empty.

The subsystem `legacy_ordinal` is a genuine wire field: current writers
always store 0, but readers still consume it (tracking a running
maximum), so it must be preserved, not validated against 0. The level-5
image reserved words, by contrast, are unconditional literal zeros.

## Ranges and the follows encoding

A range record names a subsystem by three independent fields (each may
be a wildcard pattern such as `patch*`) plus version bounds.

In the *replaces* list only, patch `follows` records are mixed in front
of the ordinary records, tagged by a **negated low bound**:

```text
low  = -(max(abs(spec_low), 1))   (as a signed 32-bit value)
high = spec_high                  (unchanged)
```

A record whose low field is negative when read as signed is a `follows`
record; decode its low bound as `-low`. Never sort or normalize the raw
bounds.

`high = 0x7fffffff` is SGI `maxint` (no upper bound) in ordinary ranges.

## Compiled semantics

The descriptor is a *compiled* form of the source spec, not a lossless
decompilation:

* `replaces` and `obsoletes` compile into the same list and cannot be
  told apart afterwards.
* `replaces ... maxint` is rewritten to `image_version - 1` at write
  time (the documented `oldvers` rule).
* Unless `norep` was given, every subsystem gains implicit replacement
  records for itself, `maint*.<name>` and `patch*.<name>`, all with
  bounds `[0, image_version - 1]`.
* Patch subsystems are written with their `required`/`default` flag
  bits stripped, and their `D` attribute blobs suppressed.

## Attribute tags

Attributes appear on products (level 7+), images and subsystems
(level 8+). Confirmed tags:

| tag | meaning | payload |
|-----|---------|---------|
| `m` | `mach` hardware expression (product, image **and** subsystem level) | expression text |
| `R` | `required(expr)` | hardware expression |
| `D` | `default(expr)` | hardware expression |
| `M` | `miniroot(expr)` | hardware expression |
| `A` | `autominiroot(name low high)` | dotted name + decimal bounds |
| `T` | disk-space accounting | `path` + five numbers, `0x01`-separated |
| `C` | product cut point | `path` + sequence number, `0x01`-separated |
| `I` | inplace content present marker | empty |
| `P` | product id | `stamp` or `stamp_first-image-version` |

Tags `B` (instbootstrap version), `S` (bootstrapmandatory), `O`
(inheritsoverlay) and `0`–`4` (dontinherit records) are defined by the
format but not present on the observed media. Unknown tags must be
preserved uninterpreted.

`T` blobs record per-filesystem-tree disk-space sums; the exact
arithmetic is writer-internal. A reader only needs to preserve them.

## Flag bits

Subsystem flag word:

| bit | meaning |
|-----|---------|
| `0x0001` | `required` |
| `0x0002` | `default` |
| `0x0400` | `patch` |
| `0x0800` | inplace (the default; **cleared** for miniroot subsystems) |
| `0x2000` | `clientonly` |
| `0x4000` | overlay product member |
| `0x8000` | `overlays` (overlay subsystem) |

The conditional statements `required(expr)`, `default(expr)` and
`miniroot(expr)` set the same bits *and* emit the corresponding
`R`/`D`/`M` attribute blobs, so a set bit with no blob means the plain
form and a set bit with blobs means the conditional form. `miniroot`
decodes from the *cleared* `0x0800` bit the same way.

Older tools leave additional transient bits (`0x0008`–`0x1000`) on disk;
they carry no persistent meaning and must be ignored.

Product flag word: `0x0800` inplace, `0x8000` overlay product.
Image flag word: `0x0800` inplace, `0x4000` overlay member.

## Prerequisites

Prerequisite clauses are two-level: ranges inside one clause are AND-ed,
separate clauses are OR-ed. `prereq(A B)` followed by `prereq(C)` means
`(A AND B) OR C`.
